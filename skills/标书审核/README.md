## 1. 技能用途与定位

本技能基于评委/专家视角的投标文件互审实践沉淀而成。其核心定位是**对照招标文件客观审查投标文件**，重点排查硬伤、漏项、自相矛盾、格式错误与扣分风险。

### 核心原则
1. **不改标、不重写**：严禁自行修改或重写方案正文；
2. **只陈述客观事实**：问题须有具体出处与依据，支持通过 Word `Ctrl+F` 快速检索定位；
3. **输出禁令**：**严禁**出具「通过 / 有条件通过 / 打回 / 建议放行」等放行结论，放行决策权归属于用户/CEO。

### 三种工作模式与交付物

| 模式 | 场景定位 | 主交付物 | 评分要求 |
|:---|:---|:---|:---|
| **模式 1** | **组内投标互审** | **Word 批注与标黄稿**：在被审 Word (.docx) 上针对问题句高亮标黄并插入结构化批注；保留只读原件 | 可选测算；终评互审才强制评分表 |
| **模式 2** | **阶段性文档审核** | **详细问题清单 Markdown**：A/B/C/D 四级问题表 + 规范书覆盖对照表 + 建议不改项 | 不出正式评分表 |
| **模式 3** | **终稿审核** | **详细问题清单 Markdown** + 规范书覆盖对照 + 补充 22 条核验 + **严格按招标公式的评分结果表** | 必须包含完整评分表 |

## 2. 与质量工程师的协同配合

本技能设计为审核 AI 与**质量工程师**紧密配合的协作机制：

### 2.1 角色分工与职责边界
- **审核 AI**：作为评委视角的互审员，执行全文段落、表格与材料的细颗粒度比对，完成客观事实挖掘、定位关键字提取与初稿形成；
- **质量工程师**：负责流程门禁管控、材料齐备性复核、任务场景卡派发、审核结果双轨核验（V9.0 硬规则 + 22 条异常相似排查），并作为唯一向 CEO/用户提供放行建议的人工把关角色。

### 2.2 接活双步门禁（信息未齐禁止开审）
凡标书相关审核，**禁止直接开审**，必须由质量工程师与用户交互完成两步门禁：
1. **步骤 A — 弹窗选定场景**：
   - 质量工程师向用户发起选项卡片（Widget），明确本轮为：`1. 组内投标互审`、`2. 阶段性文档审核`、`3. 终稿审核` 或 `4. 改稿复核`。
2. **步骤 B — 问齐材料清单**：
   - 项目短名（落盘路径依据）
   - 招标/标底完整位置（招标文件、须知前附表、技术规范、商务规范、评标办法、格式表样）
   - 被审文件路径（模式 1 必须提供可编辑的 `.docx`）
   - 本轮不审范围（若声明人员后补，内容空不报漏项，但表结构错误仍报）
   - 是否输出终评完整评分
   - （复核场景）上一轮意见/批注稿路径

### 2.3 双轨验收与复核机制
- **内容验收**：结合 `refs/bid-acceptance-checklist-v9.md`（V9.0 硬规则）逐项核验前置门禁、目录规范、评分点覆盖等；
- **异常相似与串标排查**：依据 `refs/bid-collusion-checklist/标书审核补充清单.md` 对时间戳、模板、制作环境、作者元数据等 22 项进行逐条核验，输出客观事实记录。
