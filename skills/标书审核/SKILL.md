# 标书审核

对照招标文件审投标文件（评委互审视角）。**不改标正文内容来「重写方案」**；组内互审允许在被审 Word 上**插入批注并标黄问题**作为交付件。只陈述检查事实；**禁止**写「通过 / 有条件通过 / 打回」等放行结论。放行由用户决定。

详细检查点见技能内 `refs/`：

- `refs/标书审核方法-给审核AI.md`
- `refs/标书审核方法-质量工程师版.md`
- `refs/标书互审意见-输出模板.md`（模式 2/3 清单骨架；模式 1 批注文案可参照问题表字段）
- `refs/bid-acceptance-checklist-v9.md`
- `refs/bid-collusion-checklist/标书审核补充清单.md`

模板类配套见技能内 `templates/`（详见下文「终稿审核固定模板」）。

重活（全文抽取、批量比对、批注/高亮生成等）优先交给本机可用的无头 CLI 或任务系统执行：先写 prompt 文件，再按该环境惯例提交任务并记下任务 ID/受理回执；跑完自己读任务结果文件、核对产出后再交付。不要用长 Shell/python 脚本硬扛重活（短命令 `ls`/`test` 除外）。具体命令、模型名、超时参数以本机环境为准，本技能不固定写死。

**回报第一行必须写**：`是否调用重活 CLI：是/否`（否须写原因）；漏写视为未完成。

## ★ 接活门禁（先弹窗，信息齐了再干活）

凡标书相关审核，**禁止直接开审**。

### 步骤 A — 弹窗选本轮场景

用选项卡片（widget）问用户：

1. 组内投标互审（交付：**批注+标黄 Word**）
2. 阶段性文档审核（交付：**详细问题清单**）
3. 终稿审核（交付：**详细问题清单 + 评分**）
4. （可选）改稿复核

接活弹窗由**质量工程师**向用户发起（CEO 只派活、不代弹场景卡）。若任务缺场景/路径，质量工程师必须自己弹窗补齐后再开审。

### 步骤 B — 问齐材料

| 必问项 | 说明 |
|--------|------|
| 项目短名 | `<工作目录>/<项目短名>/` |
| 招标/标底完整位置 | 目录或文件清单 |
| 审核依据文件 | 前附表/评标办法/商务规范/技术规范/格式表等 |
| 被审文件 | 路径；模式 1 必须是可编辑的 **Word(.docx)** |
| 本轮不审范围 | 无则写「无」 |
| 是否终评完整评分 | 模式 3 必须；模式 1 默认不强制评分表 |
| 上一轮意见/批注稿路径 | 仅复核需要 |

**信息未齐 = 不开审。**

## 三种模式与交付物（关键）

| 模式 | 主交付物 | 评分 |
|------|----------|------|
| **1 组内投标互审** | **在被审 Word 上插入批注，并把问题原文标黄**；另存为批注稿（勿覆盖原件）。可附极简索引 md（问题号↔批注位置），**不以**长篇问题清单 md 为主交付 | 可选测算；终评互审才强制评分表（可另附 md） |
| **2 阶段性文档审核** | **详细问题清单** md（A/B/C/D 表 + 覆盖对照 + 建议不改）；专员稿可附 V9 检查结果 | **不出**正式评分表 |
| **3 终稿审核** | **详细问题清单** md + 覆盖对照 + **《招标文件评审要点梳理》**（按固定结构）+ **补充 22 条自查表**（按 `templates/` 原表填）+ **评分结果表**（含价格分测算）；建议并行 V9 摘录 | **必须** |

统一落盘：`<工作目录>/<项目短名>/`

- 模式 1 文件名示例：`{商务|技术}-互审批注-{投标人}-{分册}.docx`（源文件复制后批注）
- 模式 2/3 文件名示例：`{商务|技术}投标文件互审意见-{投标人}-{分册}[-复核|-终评].md`

---

## 模式 1 专规 — Word 批注 + 标黄

1. **复制**被审 docx 再改，原件只读保留。  
2. 每个问题在对应段落/句子：  
   - **字体/底纹标黄**（突出问题句，勿整章乱涂）  
   - **插入 Word 批注**：批注文案建议含 `号（A1…）+ 问题一句话 + 对应招标条款/影响 + 整改要点`；须能对上定位关键字  
3. 批注作者可用「质量审核」等固定名。  
4. 多家投标人：**每家一份**批注 Word。  
5. 无法在 Word 内表达的汇总（如补充 22 条、评分拼图）可另附短 md，但**主交付仍是批注 Word**。  
6. 仍禁止放行结论话术；批注里写风险事实与整改，不写「打回/通过」。

实现：用重活 CLI/本机脚本操作 docx（如 python-docx 批注与高亮）；做完 `test -f` 核对批注稿路径。

---

## 模式 2 / 3 专规 — 详细问题清单

套用 `refs/标书互审意见-输出模板.md`：

1. 文首元数据（含模式、标底路径、依据文件）  
2. 怎么用（Ctrl+F）  
3. 总判断 3～5 条硬事实  
4. 问题表列名固定：号 | 问题 | 参考页 | 定位关键字 | 命中 | 影响与整改（A/B/C/D）  
5. 技术册覆盖对照；文末建议不改；复核闭环表  

模式 3 另加评分（先抄招标公式；乐观/中位/悲观；还能抢的分）+ 补充 22 条（按 `templates/` 原表）+ 评审要点梳理（按下文固定结构）。

### 终稿审核固定模板（必须照做）

1. **《招标文件评审要点梳理》** → 出 `招标文件评审要点梳理.md`（可另导 docx/pdf），结构固定：
   抬头信息表（项目名称/招标编号/招标人/招标代理/资格审查方式/评标方法与分值构成/投标有效期/投标保证金/服务范围/服务期限/递交截止时间）→ 一、废标项（否决投标条款）汇总，分 ①报价红线 ②文件与资格红线 ③技术实质（★）条款红线 ④行为与异常报价红线，每类用两列表「红线情形｜具体说明」→ 二、得分要求（评标办法·评分标准），逐项抄分值与评分规则。每条再加一列「本标书核对结果（满足/不满足/待补 + 定位）」。内容全部摘自本项目招标文件原文，不编。

2. **补充 22 条自查表**：复制 `templates/补充22条自查表-原表.xlsx` 另存为 `补充22条自查表-<项目短名>.xlsx`，保留表头（商机编码、招标编号）、序号/类别/检查内容/核查要点/要求列和底部签字栏，逐条填「检查结果」；只能凭我方文件核查的写结论，需比对其他投标方或系统记录的写「需人工核查：…」，不臆测。

3. **价格分（基准价法）测算**：终稿评分里的价格分按下列框架算，并在评分结果表单列「价格分测算」。**先核对本项目招标文件评标办法，参数不一致一律以招标原文为准并改参数**：
   - 评标价 = 不含税价款（承诺开专票）；
   - 有效家数 N≥5 时去掉 1 个最高、1 个最低评标价后取平均；N<5 不去高低，全体直接平均；
   - 基准价 J = 平均价 × 基准系数（常见 95%，以招标原文为准）；
   - 等于 J 得该价格项满分（满分分值以招标原文为准，常见价格满分 40 分）；高于 J 每高 1% 扣 X 分，低于 J 每低 1% 扣 Y 分（常见 X=1、Y=0.5），线性取值、保留两位小数、扣完为止；
   - 被剔除的 1 高 1 低仍照公式计分；
   - 报价高于最高投标限价（含税/不含税口径以招标原文为准）→ 否决投标；
   - 异常低价审查阈值按招标原文（常见口径：低于全部有效报价平均值×50%、次低报价×50%、最高限价×45% 之一即启动书面说明/审查）；
   - 报价未知时只给公式和「贴近 J 的建议报价区间」，不编竞争对手报价；用示例数据测算须标明「示例数据」。

## 0. 角色与边界

**做：** 对照招标找硬伤/漏项/矛盾/格式/给分风险；每条可 Ctrl+F；资格≠评分≠观感；「人员后补」时内容空可不报漏项，表结构错仍报。

**不做：** 未要求不重写方案正文；不用空话；不发明规则；商务问题不塞进技术册清单；前附表优先于正文冲突条款。

**输出禁令：** 禁止通过/有条件通过/打回/建议放行；禁止按阻断/警告做放行汇总。

---

## 1. 开工必读

先招标后投标：前附表 → 评标办法 → 商务规范 → 技术规范 → 格式/表格。锁定截止、服务期周数、分值构成、业绩窗口。

---

## 2. 通用流程

```
接活门禁 → 读招标四件套 → 抽投标全文
→ 形式/模板 → 规范书覆盖 → 评分点（模式3）→ 一致性/痕迹
→ 按模式交付（1=批注Word；2/3=详细清单md）
→ 复核另存，不覆盖旧稿
```

---

## 3. 检查类别（换项目保留）

形式资格；编制模板；规范书应答；评分点材料；人员证明格式；业绩知产；商务其它；一致性；AI/制作痕迹；补充 22 条。

---

## 4. 完成标准

- 已弹场景 + 材料信息齐  
- 模式 1：存在可打开的批注+标黄 docx，问题句可见高亮与批注  
- 模式 2/3：详细问题清单完整；模式 3 含评分拼图  
- 无放行结论话术；路径已回报
