# 标书验收清单（V9.0 硬规则）

> **适用技能**：小波标书助手 V9.0（`bobobiaoshu-skill`）  
> **用途**：质量工程师侧给 CEO 的放行验收勾选表  
> **严重度约定**：
> - **【阻断】** = 不过不放行（须修复后复验）
> - **【警告】** = 须记录；严重时可升为阻断（升格规则见各条及末尾「升格规则」）
>
> **脚本路径基准**：技能目录下 `scripts/`（下文命令均相对该目录）

## 十、审核脚本速查（通过 / 不通过）

| 脚本 | 典型命令 | 通过 | 不通过 / 处理 |
|------|----------|------|----------------|
| `eval_required_headings.py` | `report …` / `check …` | exit 0，`all_covered`，✅ 全部覆盖 | exit 1，有缺失 → **阻断**，补 H2 |
| `eval_mapping.py` | `report` / `check` | 技术主观「未映射」=0；建议映射已人工确认 | 未映射残留 → **阻断** |

| `relevance_check.py` | `check <稿> --tender … --project …` | 高(≥60)可改写使用；终稿无严重污染 | 低(<35)弃用；中须大改；强行用低分 → **阻断** |
| `snippet_adapt.py` | `check … --project --company --system` | ✓ 未发现原项目专属字眼 | 有残留 → **阻断**，adapt/手改后复检 |
| `consistency_check.py` | `<docx\|md> [--vocabulary …]` | 无 issues（理想）；验收按 error/warning 拆 | error（术语/禁用词）**阻断**；warning 记录，严重升格 |

> **说明**：`consistency_check` / `doc_quality_check` 对「任意 issues」exit 1；CEO 验收时勿把「仅有 warning」与「有 error」混为一谈——清单以严重度列为准。

## 十一、升格规则（警告 → 阻断）

以下情况警告必须升为阻断（技能或脚本已暗示）：

1. 「建议映射」经人工确认后实际未覆盖评分点。  
2. 相关性「中」的片段未大幅改写即入终稿，或终稿仍有跨领域污染。  
3. 数值冲突涉及响应时限、人员数量、SLA 等评分/承诺项。  
4. AI 特征词 / 夸大表达在 `doc_quality_check` 中大量出现，或与去 AI 专项清单重叠。  
5. 字数检查「找不到分值」的章节实际对应评分项却被跳过。  
6. 段落结构/表格缺失导致评委无法对照评分点（结合评分表人工判断）。
