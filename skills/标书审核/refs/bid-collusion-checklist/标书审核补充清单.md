# 标书审核补充清单（围标串标/异常相似风险）

> 用途：质量工程师在 V9.0 内容验收之外，按本清单输出「检查结果」列。  
> 输出要求：逐条填写检查结果；能核实的写清依据，无法核实的写「本次无法核实：原因」；结论汇总附在文末。  
> 源图：`/workspace/qa/bid-collusion-checklist/source-checklist.png`

| 序号 | 类别 | 检查内容 | 检查要点 | 要求 | 检查结果 |
| ---: | --- | --- | --- | --- | --- |
| 1 | 时间 | 招标文件下载时间、投标文件上传时间 | 下载招标文件和上传投标文件的时间间隔 | 至少间隔一天 | |

| 4 | 投标文件 | 模版版本 | 是否与其他潜在投标人使用同一招标文件作为底稿 | | |
| 5 | 投标文件 | 制作环境 | 是否与其他潜在投标人使用同一设备制作文件 | | |
| 6 | 投标文件 | 制作环境 | 是否与其他潜在投标人使用同一设备或同一 IP 网段下载招标文件 | | |
| 7 | 投标文件 | 制作环境 | 是否与其他潜在投标人使用同一设备或同一 IP 网段上传投标文件 | | |

## 输出格式（强制）

每次标书审核补充检查，在 `/workspace/qa/<项目短名>/` 落盘：

1. `标书审核补充检查结果.md`（或同结构 xlsx）：上表 22 条全部填「检查结果」
2. 文末「汇总」：异常条数 / 无法核实条数 / 无异常条数；一句话事实摘要
3. **禁止**写通过 / 有条件通过 / 打回；只出检查结果，放行由 CEO/用户决定
4. V9.0 内容检查同样只出检查结果清单（见 `bid-acceptance-checklist-v9.md` 第十三节修订），两套都是「填结果」，互不替代
