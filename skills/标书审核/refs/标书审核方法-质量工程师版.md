# 标书审核方法（质量工程师版）

本手册为质量工程师在共享 Linux 工作台执行标书质量审核的主方法规范。任务核心是**对照招标文件审投标文件**，发现缺陷与风险，不改标、不写标。

---

## 0. 角色与边界

质量工程师是评委视角的互审员，不是投标文件的编写者。

### 0.1 工作原则（做）
- **对照招标文件找问题**：重点排查硬伤、漏项、自相矛盾、格式错、给分风险。
- **定位可复查**：每条问题必须能通过 Word `Ctrl+F` 快速检索定位。
- **三层区分**：明确区分「资格（过/不过）」≠「评分（得多少分）」≠「观感（编制规范分）」。
- **特定声明处理**：当任务声明「人员后补」或「本轮不审商务」时，对应内容空缺不作为漏项问题，但**表格结构错误、表头缺漏仍须如实指出**。

### 0.2 工作禁区（不做）
- 未获明确指令，**严禁修改投标文件原文**。
- **严禁空话套话**：禁止使用「建议进一步完善」「整体较好」等模糊评价替代具体问题。
- **严禁臆造规则**：不得发明招标文件未规定的评分或废标标准。
- **分册独立**：技术册清单中不直接罗列商务册问题（若有因果或关联，注明「交叉提示：见商务册第×页」）。
- **文件效力原则**：须知前附表与正文发生冲突时，**以前附表为准**（例如前附表要求偏离表填「全部满足」，其效力高于正文「空表视为满足」）。

### 0.3 本工作台硬约束
1. **禁止下放行结论**：只输出客观检查结果、事实与问题清单，**绝对禁止**写「通过 / 有条件通过 / 打回」。
2. **禁止放行汇总清单**：**绝对禁止**按【阻断】/【警告】做放行勾选汇总或打回清单。
3. **分级不等于放行**：A/B/C/D 仅为问题严重度分级（必须改 / 漏项 / 编制 / 人员格式），**绝非**放行依据；文首总判断仅罗列硬事实，**严禁**出现「建议放行」「准予投标」等放行话术。
4. **并行交付三件套**：所有产出统一存放在同一项目目录 `/workspace/qa/<项目短名>/`：
   - `标书互审意见-*.md`（按本手册第 3 节及输出模板格式输出）
   - `标书V9检查结果.md`（按 `bid-acceptance-checklist-v9.md` 第十三节：逐条检查结果 + 脚本摘录 + 汇总异常/无法核实/无异常）
   - `标书审核补充检查结果.md`（按 `bid-collusion-checklist/标书审核补充清单.md`：22条逐条检查结果 + 汇总）
5. **执行工具与权限规范**：
   - 执行环境为共享 Linux 工作台，使用 `/usr/local/bin/agy` 无头模式运行。
   - 质量工程师只负责编写执行指令、核对产出事实、整理问题清单、向 CEO 回报产出路径。
   - **严禁**调用 ExternalShell，**严禁**打扰或触碰用户 Windows 环境。
6. **回报路径**：标书是否放行由 CEO 或最终用户决定；审核完成后仅向 CEO 回报产出文件路径，不主动向用户汇报。

## 1. 开工必读顺序（不读完不准出清单）

审核前必须严格按照以下顺序研读招标文件，不得跳步，更不得在未读完招标文件前直接翻看投标文件：

| 顺序 | 文件类别 | 重点抽取信息 |
|:---:|---|---|
| **1** | 招标文件 + 须知前附表 | 项目名称、招标编号、是否划分标包、投标截止时间、投标有效期、保证金要求、签字盖章要求、偏离表特殊规定、服务期/交付期要求。 |
| **2** | 附件1 评标办法 | 初步评审（形式/资格/响应性）逐条废标项；详细评审每个评分点的**原文公式、评分注释、不得分与扣分条件**。 |
| **3** | 附件2 商务规范书 | 合同服务期、付款方式与节点、考核与扣款办法、各项承诺书必填字段（如信息安全责任人等）。 |
| **4** | 附件3 技术规范书 | 技术方案必含章节目录、功能清单、培训/考核/团队角色原文要求、是否存在 ★ 关键指标。 |
| **5** | 第六章格式 + 附件4 表格 | 封面、索引表列、偏离表列名、表一～表六字段。**注：若招标模板本身缺少序号（如缺序号4），必须严格保留该缺失，严禁私自顺延修正**。 |

读完后必须在脑中锁定关键数据基准（换项目时按新招标替换）：
- 投标截止时间（如：2026-09-03）
- 履约服务期（如：合同签订之日至 2026-12-31，折算实际工期周数）
- 分值构成比例（如：技术 50 + 商务 10 + 价格 40）
- 同类业绩窗口期与界定口径（如：近3年，合同标的须为开发实施而非纯运维）

## 2. 审核流程

```text
研读招标文件套件
    ↓
抽取评分公式 + 规范书必含项 + 格式表样
    ↓
抽取投标文件全文（正文段落 + 全部表格 + 证件合同扫描件 OCR）
    ↓
先核形式/模板 → 再核规范书覆盖 → 再核评分点打分 → 再核一致性/造假观感
    ↓
并行执行 V9.0 检查与补充 22 条检查
    ↓
输出标书互审意见 md（按第 3 节规范）与配套检查结果
    ↓
若为改稿复核：逐条核对上一轮清单（判定 已改 / 部分改 / 未改 / 回潮）
```

### 抽取与核对规范
- **表格必须整表提取**：核对列名、行数及字段完整性，切勿只看表格标题。
- **证件合同必须核验原图**：营业执照、身份证、资格证书、合同关键页、开户许可证等必须核验扫描件，不得仅凭正文文字判定。
- **页码漂移与关键字定位**：排版过程中页码极易发生变化，**所有问题定位一律以关键字为准**，页码仅作大致参考。
- **多处命中处理**：当定位词在多处出现时，必须注明「第几次命中」或「避开索引表直接定位正文」。

## 3. 强制输出格式

每份审核报告落盘至 `/workspace/qa/<项目短名>/`，命名规范：
`{商务|技术}投标文件互审意见-{投标人}-{分册}[可选-复核|终评].md`

### 3.1 文首元数据（每份必备）
```markdown
# {商务|技术}投标文件互审意见（{投标人}·{分册}）

**项目名称**：…
**招标编号**：…
**被审文件**：路径 + 约 xx 页 + 文件日期
**对照文件**：附件1 / 2 / 3 / 招标须知前附表 / 第六章格式（写明本轮实际使用的文件）
**本轮不审**：用户明确划除的范围（如商务册、人员证件等；无则写「无」）
**审核日期**：YYYY-MM-DD
**证件OCR**：是否逐张执行 OCR（未执行则如实写「未执行」）
```

紧接固定使用说明段：
> **怎么用**：Word 打开投标文件，`Ctrl+F` 搜「定位关键字」。页码会漂，以关键字为准。「全文无命中」表示功能或章节缺失。复核稿请重点核验「怎么搜验证」。

### 3.2 一、总判断（事实陈述）
- 列出 3～5 条核心硬事实，直指要害，每条对应后文具体问题编号。
- **严禁客套话**，严禁先扬后抑。
- **严禁写放行结论**：不得出现「通过 / 有条件通过 / 打回 / 建议放行」等字眼。
- 终评稿可客观罗列测算出的分数区间。

### 3.3 二、问题清单
按严重度分级呈现，禁止按章节流水账罗列：

| 级别 | 级别含义 | 典型问题示例 |
|:---:|---|---|
| **A 必须改** | 触碰废标条款、资格不符、评分公式直接归零、工期排期不可行、重大偏离 | 授权书空白、成立时间写错、工期超出服务期、擅改考核办法、错贴索引表 |
| **B 规范书漏项 / 打架** | 方案完整性缺失、前后表述矛盾 | 查询统计缺少必含维度、前后接口协议打架、核心管理角色缺失 |
| **C 模板 / 编制** | 扣编制规范分、影响评委检索 | 索引表页码空白、占位符残留、封面信息缺失、承诺项序号断档、交叉引用幽灵章节 |
| **D 人员 / 证明格式** | 人员后补前必须先修正表格框架；内容允许后补 | 人员表角色与姓名串列、履历表未套用原表、自拟知识产权清单 |

**问题表结构（必须严格保持此列名与顺序）：**

| 号 | 问题 | 参考页 | 定位关键字 | 命中 | 影响与整改 |
|:---:|---|:---:|---|---|---|
| A1 | 一句话简述，**加粗核心事实** | 约 xx 页 | 可直接粘贴进 Word 的短词 | 第几次 / 无命中 / 具体所在章节 | 对应招标条款原文 + 具体整改措施（严禁只写「建议完善」） |

**复核稿专属闭环表（可选）：**

| 原号 | 问题简述 | 结果（已改 / 部分改 / 未改 / 回潮） | 怎么搜验证（期望命中内容或命中数应为 0） |
|:---:|---|:---:|---|

### 3.4 三、技术册覆盖对照表（技术册必做）
格式如下：

| 规范书条款 / 原词 | 判定 (✅/⚠️/✗) | 怎么搜 |
|---|:---:|---|
| 技术规范书核心条款原文 | ✅/⚠️/✗ | 精确检索词与定位说明 |

*注：仅有章节标题但正文未包含规范书原词的，判定为 ⚠️，不得标记为 ✅。*

### 3.5 文末「核对后建议不改」
列出经核对属于招标文件原样瑕疵或特定设计、无需整改的事项（例如：招标文件模板本身缺序号 4，投标文件沿用不改）。防止错误反馈导致二次失误。

## 4. 检查点总表

换项目时**根据新招标文件替换具体条目与公式，检查类别完整保留**。

### 4.1 形式与资格检查
| 检查点 | 核验方法 | 风险事实与教训 |
|---|---|---|
| 投标人名称一致性 | 核对封面、投标函、营业执照扫描件 | 名称必须一字不差；变更过的须附工商变更证明 |
| 投标函基本信息 | 对照前附表核对项目名、编号、有效期 | 严禁残留 `【招标人名称】`、`/ 标包` 等未替换标记 |
| 投标保证金 | 对照前附表要求核对 | 前附表若明确「无需提交」，填 `/` 即可，不视为漏填 |
| 授权委托书 | 检查正文及身份证明 | 有标题必须有正文；法定代表人亲自投标须明确声明不涉及 |
| 法定代表人证明 | 核对姓名、成立时间、身份证正反面 | 成立时间必须与执照完全一致（切勿出现未来年份等荒谬错误） |
| 签字盖章位置 | 检查各表落款及印章预留位 | 电子标认 CA 签章，文档仍须规范保留法定落款区域 |
| 资格业绩有效性 | 窗口期内 ≥1 个同类**开发实施**合同关键页 | 纯运维/纯集成合同不能撑开发资格业绩；必须含标的、金额、盖章页 |
| 联合体与代理商 | 检查承诺函与资质证明 | 按招标要求核对，未按格式提供属于形式缺陷 |
| 不良信用记录 | 裁判文书网、失信被执行人、信用中国截图 | 截图查询主体、时间需符合要求；不可用执行网截图替代信用中国 |
| 投标有效期 | 投标函承诺天数 | 必须满足或优于招标文件规定天数 |

### 4.2 编制与模板检查
| 检查点 | 核验方法与要求 |
|---|---|
| 索引表准确性 | 技术册必须采用技术评分点索引表，严禁误贴初步评审表。 |
| 索引页码回填 | 正式稿必须回填真实页码；涉及商务册内容标注「见商务册第×页」；删除省略号 `……`。 |
| 封面要素 | 项目全称、招标编号、标包标识、投标人全称、投标日期齐全。 |
| 偏离表规范 | 列名严格采用招标原表结构；注明项目名与编号；每项条款逐条应答，至少包含「全部满足」或「无偏离」。 |
| 目录对齐评分点 | 技术建议书各章节标题必须直接对应评分点名称，便于评委检索打分，切勿自拟脱节架构。 |
| 额外承诺与补充文件 | 严禁出现未填写的占位序号（如仅剩 `1. 2.`）；承诺必须可量化且具备增值意义；补充文件须精准指向章节。 |
| 占位符与示例清理 | 全文清查并删除 `【】`、`（示例）`、`XX年` 等草稿残留标记。 |
| 交叉引用有效性 | 排查文中引用的节号、图表号，严禁出现已删除或编号变动引起的「幽灵引用」。 |
| 标题灌水防范 | 严禁多级标题无意义堆叠复用同一套泛化骨架，影响编制分与针对性评价。 |

### 4.3 技术规范书应答
- **必含结构要素**：总体技术方案、设计原则、方案优势、优化设计思路缺一不可。
- **方案六大板块**：开发方案、测试方案、集成部署、应急保障、质量管理、进度流程控制。
- **管理与服务要素**：需求管理计划、项目组织架构、交付保障、风险控制、保密体系、培训体系（目标/内容/流程/课程）、技术支持。
- **原词精确应答**：必须使用规范书原词检索应答，禁止擅自做同义词替换（如将「快速过滤器」改写为「高级查询」会被判定漏项；考核指标权重禁止擅自调整）。
- **前后矛盾专项清查**：
  - 同一接口在不同章节技术路线不一致（如一处写 REST、另一处写 gRPC）。
  - 工期描述出现多套冲突口径（如正文写 13 周，甘特图画 26 周，某处又写 44 周）。
  - 服务响应 SLA 出现多套标准（如 30 分钟 vs 2 小时 vs 4 小时）。
  - 项目团队人数跨章节打架（如人员表 12 人，方案表述 18 人）。
  - 将投标人拟定指标误标为「来源：技术规范书」。
- **工期进度铁律**：按投标截止时间倒推，实施计划总工期必须能完整容纳在招标要求截止日期内；甘特图时间刻度必须与实际投标时间完全吻合。

### 4.4 评分点打分审查
- **公式对齐**：先完整摘录招标文件评分标准原公式，再逐项代入投标文件支撑材料。
- **零分硬规则**：招标文件明确规定「未提供证明材料不得分」的项，若材料缺失，直接计 0 分，严禁主观同情给分。
- **客观项精确计算**：业绩数量与金额、人员证书与人数、知识产权数量等，依据有效材料严格核算。
- **主观项审慎分档**：实施方案、开发过程、服务方案等主观评分项，按优/良/中/差客观分档，存在缺项或矛盾的坚决降档。
- **跨册材料明确标注**：技术册未附但商务册提供的材料，明确标注「技术册未提供，见商务册第×页」，客观提示得分风险。

### 4.5 人员与证明材料
- **表格列项规范**：表五严格区分团队角色与姓名列，严禁将岗位名称填入人名列。
- **岗位互斥审查**：项目经理与技术经理严禁由同一人兼任（兼任则相关项不得分）。
- **履历真实度核验**：严禁在履历中出现未开标的「本项目、2026年至今」等穿越描述；履历项目时间须符合逻辑。
- **社保证明合规性**：社保缴费单位必须与投标人名称完全一致；截图框选必须精准，严禁错框他人。
- **证书有效性与可溯源性**：人员证书必须在有效期内，且能在正文后附扫描件中精确翻查到对应页码。

### 4.6 业绩与知识产权
- **业绩合同三要素**：标的内容页、金额页、签字盖章页缺一不可；框架协议必须补充提供订单或结算单发票。
- **业绩明细表分类**：合同明细必须清晰标注对应「业绩-数量」还是「业绩-金额」，避免先数量后金额导致金额分落空；项目内容填写具体可查的系统名称，禁止泛写「同类案例」。
- **知识产权权属与相关性**：
  - 软著与专利权属人必须为当前投标人（曾用名须附工商变更证明）。
  - 知识产权主题必须高度契合招标技术范畴，弱相关知识产权在评审中存在得 0 分风险。
  - 技术册若未附证明文件，应建立清晰跨册索引指引。

### 4.7 商务其它合规项
- **账户信息统一**：投标函、基本情况表与开户许可证中的银行账号必须完全一致。
- **信息一致性**：企业注册地址、法人代表姓名在所有表格中保持统一。
- **控股与特定关系**：如实填写控股关联关系，清理未填写模板括号；不涉及的项目仅保留不涉及声明，切勿误附存在关联的承诺正文。
- **责任人信息完整**：安全责任承诺书等关键文件，责任人姓名、职务、联系方式必须如实填写，严禁留空。

### 4.8 一致性与造假观感防范
- 全员履历不得批量复制完全相同的起止时间与项目描述。
- 个人工作年限与履历列出时间不得自相矛盾。
- 证书发证时间、有效期限不得与人员从业年限冲突。
- 严禁出现正文引用招标文件但查无此据的情况。

### 4.9 AI 与制作痕迹排查（发现即列为 A 级重大问题）
- **底层标记清查**：检查文档隐藏文本、UUID 异常标记及 `docProps/custom.xml` 中非系统合规水印的外部痕迹。
- **排版源码残留**：正文中严禁出现 `# 标题`、````mermaid`、`flowchart` 等未渲染 Markdown 源码。
- **机械句式堆叠**：排查高频重复出现的特定模板化表达。
- **AI 尾句残留**：全文严禁出现「作为AI」「综上所述建立了完整的18个子节」等机器生成特征尾句。

## 5. 给分方法

1. **公式先行**：先摘录招标文件评分标准原公式，再套入投标文件实际材料。
2. **打分精度**：评分步长严格按 0.1 计算；给出区间时必须标明中位分。
3. **客观项不估算**：证书、人数、业绩、资质等可数项必须算出精确数值。
4. **主观项科学分档**：方案针对性、完整性、可行性按档位划分（档顶 / 中位 / 档底），发现漏项或前后矛盾立即降档。
5. **未见材料坚决归零**：招标文件注明「未提供扫描件不得分」的项目，凡未见到有效证明的一律计 0 分。
6. **分册核算清晰**：本册未包含的材料注明「未评，见××册」，严禁凭空预估另一册分数。
7. **综合得分拼图**：终评报告必须汇总形成清晰的得分拼图（客观分、方案分、各分册小计、乐观/中位/悲观三线测算）。
8. **指出提分空间**：客观列出尚可通过补齐材料争取的分值（如：补齐人员证书可增几分、补报软著可增几分），为决策提供事实依据。

## 6. 复核轮次执行机制

当收到针对修改稿的复核任务时：
1. **逐条对账**：调出上一轮互审意见清单，对 A/B/C/D 类问题逐条通过关键字检索验证，严禁凭印象判定。
2. **严防问题回潮**：重点核查易回潮项（如：重新排版后索引页码再次留空、额外承诺项再次变回 `1. 2.`、章节自动编号再次丢失等）。
3. **新增内容全量扫描**：对新插入的人员、业绩、技术方案章节，按第 4 节标准重新完整扫描一遍。
4. **页码漂移校准**：以最新稿件的实际页码为准，建立准确的位置参照。
5. **版本留痕**：复核结果另存为「复核稿」或「终评稿」，严禁直接覆盖历史审核文件。

## 7. 典型反面教材（校准风险嗅觉）

| 典型硬伤现象 | 严重后果与风险归类 |
|---|---|
| 技术索引表误贴为初步评审表 | 评委无法按评分点索引，编制分扣减，评审体验极差 |
| 实施计划周数超出服务期截止日 | 方案可行性归零，严重影响主观评分甚至构成重大偏离 |
| 自行更改招标文件考核权重与扣分标准 | 擅改招标人规则，构成实质性负偏离 |
| 人员履历中出现未开标的「本项目」履约记录 | 存在虚假应标严重嫌疑，引发合规风险 |
| 项目团队人数刚好等于加分基准人数 | 未能获得任何额外数量加分（如基准10人，报10人加0分） |
| 知识产权提供弱相关运维证书或直接空缺 | 明确要求「未提供不得分」直接导致相应分值全扣 |
| 业绩表未明确标注属于数量还是金额 | 按先数量后金额规则结算，可能导致金额加分项直接计 0 分 |
| 将纯运维/纯供货合同用于开发实施业绩 | 资格审查被直接剔除，或评分项不予认定 |
| 成立时间填写为未来年份 | 基础信息与执照打架，形式审查重大事故 |
| 授权委托书留空或缺少法定身份证明扫描件 | 形式评审直接否决投标 |
| 正文残留 Markdown 代码块或 AI 总结尾句 | 造成极差的评委观感，可能被认定为编制质量不合格 |
| 核心接口协议跨章节出现 REST 与 gRPC 矛盾 | 技术方案自相矛盾，直接暴露方案拼凑硬伤 |

## 8. 工作纪律与执行规范

- **检索词真实存在**：提供的定位关键字必须是文档中真实存在或确证缺失的词汇，严禁自行编造搜不到的同义词。
- **报无命中前自我验证**：在问题清单中判定「无命中」前，审核人员必须自行核查可能存在的近义表述，避免误报。
- **问题分析深入透彻**：指出缺陷必须精准到具体列、具体段落及具体冲突条款，给出明确整改方向。
- **合并清单保留原号**：汇总或复核他人清单时，严格保留历史原编号，便于全流程对账闭环。
- **区分模板瑕疵与编写错误**：严禁将招标文件原样存在的格式缺陷（如缺序号4）误报为投标文件编制错误。
- **严守审核边界**：不主动审查商务报价策略、串标降价等非委托范围，除非收到专门专项任务。
- **事实第一，禁止放行判定**：输出仅陈述客观检查事实与数据，放行决定权归属 CEO 与用户。
- **成果回报路径**：所有产出整理完成后，统一将文件路径汇报给 CEO，不直接向用户发送未经确认的信息。
